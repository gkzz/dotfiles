# Grill Me

計画・設計・アイデアを決定木として捉え、共通理解に達するまで質問を続ける。曖昧な回答や楽観的な前提をそのまま受け入れず、矛盾、未定義、失敗条件を具体化する。

## 進め方

1. 会話から対象を特定する。対象が分からない場合だけ、何を検証するか尋ねる。
2. リポジトリ、文書、設定、履歴、利用可能な外部情報を調べれば分かる事実は自分で確認する。ユーザーには、選択やトレードオフを伴う決定だけを尋ねる。
3. 他の判断を左右する上流の決定から、必ず一度に一問だけ尋ねる。回答を受けるまで次の質問へ進まない。
4. 各質問では、重要な理由、具体的な選択肢、推奨案とその理由を示す。自由回答が適切なら、無理に選択肢へ限定しない。
5. 回答ごとに決定木を更新する。新しい依存関係や矛盾が生じた場合は、その枝を先に深掘りする。
6. スコープと非ゴール、利用者、データと状態、依存関係、失敗モード、復旧、セキュリティ、運用、移行、検証方法、段階的な提供を必要に応じて確認する。関係のない論点を形式的に質問しない。
7. 前提が解決した未決定事項がなくなったら、共通理解に達したか確認する。ユーザーが確認するまで、実装、ファイル変更、チケット起票などへ進まない。

質問は必ず次の形式で行う。`AskQuestion` Tool や `AskUserQuestion` Tool は使用しない。

```markdown
### ❓ Q[番号]: [質問文]

[なぜこの質問が重要か]

- **A** — [選択肢]
- **B** — [選択肢]
- ...

**推奨: [A/B/...]** — [理由]
```

## 終了時

共通理解に達したら、次を簡潔にまとめる。

- 決まったことと理由
- 今回扱う最小スコープと非ゴール
- 意図的に未解決のまま残す点
- 次に取る行動（必要な場合のみ）

インタビューの完了は、その後の実装や外部変更への承認を意味しない。追加の作業はユーザーの依頼または確認を得てから行う。
