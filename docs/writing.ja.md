# 日本語の執筆ガイド

利用者が手順を実行し、結果を確認できる文章にします。事実や制約を先に示し、コマンドと説明を対応させてください。

## 文章の書き方

- 一文に判断や列挙を詰め込みすぎず、長い説明は文を分けます。
- 主語と述語、修飾語と修飾先を近づけます。
- 用語と表記を文書内で揃えます。コマンド、パス、設定名はコード表記にします。
- 手順には前提条件、操作、成功の確認方法を含めます。
- 未確認の挙動を断定せず、確認できた範囲を示します。

## textlint で検査する

[開発用コマンド](USAGE.md#開発用コマンド)に従って依存関係を導入し、リポジトリルートで実行します。

```bash
make docs-lint
mise exec -- pnpm run lint:docs:fix
```

自動修正後は差分を読み、意味が変わっていないか確認してください。

対象は README、`docs/`、`.agents/skills/` の Markdown です。英語で管理する `renodash-dashboard` は除外します。英語専用ルールは導入していません。

設定は `.config/textlint/` に置きます。日本語の技術文書向けプリセットを使い、一文の長さは120文字を目安とします。文体の混在、漢字の連続、弱い表現のルールは無効にしています。スキルの指示文や技術用語も扱うためです。

指摘は文脈に沿って修正してください。例外が必要な場合は、理由と対象を明確にし、除外範囲を絞ります。
