# Linux のシェル初期化の対応方針

## 対応する問題

利用者は本人だけで、複数の私用マシンを使います。WSL 以外の Linux でも管理対象の開発ツールを利用できるようにします。

現在の `.bashrc` は、Linux では WSL と判定した場合だけ `bash/wsl.bash` を読み込みます。
Homebrew、mise、direnv の初期化はこのファイル内にあり、通常の Linux では実行されません。
mise を導入済みでも、その管理下のツールが PATH へ追加されません。

全体レビューでは、通常の Linux を模した一時 HOME に mise の代替コマンドを置き、
対話 Bash の起動時に初期化が呼ばれないことを確認しました。
実機の新規導入を通した確認は未実施です。

## 本対応で行う変更

- Linux 共通の初期化を `bash/linux.bash` に分け、Linux では WSL 判定の前に読み込みます。
- Homebrew、mise、direnv の初期化を Linux 共通処理へ移します。
- dircolors と lesspipe の設定も Linux 共通処理へ移します。
- SSH agent と WSL 用の鍵の読み込みは `bash/wsl.bash` に残します。
- WSL では共通処理の後に固有処理を読み込み、初期化の重複を避けます。
- macOS は既存の `bash/mac.bash` を利用します。

## 確認項目

- 一時 HOME と制御した PATH で対話 Bash を起動し、親シェルの設定に依存せず検証します。
- 通常の Linux で mise の初期化が呼ばれ、管理対象ツールへの PATH が有効になることを確認します。
- WSL で Linux 共通処理と固有処理がそれぞれ一度だけ呼ばれることを確認します。
- ツールが未導入の場合にもシェルを起動できることを確認します。
- macOS の起動確認と既存テスト、Bash 構文検査、文書 lint を実行します。
- 回帰を検出できるシェル起動テストを既存のテスト実行経路へ追加します。

## 実施順序

このブランチでは対応方針だけを記録し、初期化処理は変更しません。
この方針を main に取り込んだ後、main から本対応用の別ブランチを作成します。
本対応では上記を実装・検証し、確認できていない実機環境を明記します。
